# Portfolio Site

A static portfolio site generated by a small Python script (Jinja2 templates + a plain
Python data file) — no JavaScript framework, no Node.js required to build it.

## How it works

- `content.py` — single source of truth for all site copy (name, bio, skills, projects,
  experience, blog posts). Edit this file to update your content.
- `templates/` — Jinja2 HTML templates (`base.html`, `index.html`, `blog_index.html`, `post.html`)
- `static/` — CSS and JS, copied as-is into the build output
- `build.py` — renders the templates + content into `docs/` (plain HTML/CSS/JS, ready to serve)
- `docs/` — generated output. This is what actually gets deployed/served — don't hand-edit it,
  it's overwritten every time you run `build.py`.

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Building the site

```powershell
.\.venv\Scripts\python.exe build.py
```

This regenerates everything in `docs/`. Add `--serve` to also start a local server on the
result:

```powershell
.\.venv\Scripts\python.exe build.py --serve
# then open http://localhost:8080
```

## Before you share this with recruiters

Edit `content.py` and replace the placeholder values with your real:

- Name, title, tagline, email, GitHub/LinkedIn links (`SITE`)
- Bio paragraphs and stats (`ABOUT`)
- Skills (`SKILLS`)
- Projects, with real links to live demos / repos (`PROJECTS`)
- Work experience (`EXPERIENCE`)
- Blog posts, or remove the blog section from `templates/index.html` and `templates/base.html`
  nav if you don't want one (`BLOG_POSTS`)

Then add your resume PDF at `docs/assets/resume/resume.pdf` — the "Download Resume" button on
the homepage links there. Since `docs/` is regenerated on every build, keep your `resume.pdf`
outside `docs/` (e.g. in a `resume/` folder) and copy it in as part of `build.py`, or just
re-copy it after each build.

The contact form is client-side only — it validates input but does not send email yet. Wire it
to a real backend such as [Formspree](https://formspree.io) or Netlify Forms by updating the
form-handling logic in `static/js/main.js`.

Rebuild after any change: `python build.py`.

## Deploying to GitHub Pages

1. Run `python build.py` and commit the generated `docs/` folder along with your source files.
2. Push this repo to GitHub.
3. In the repo settings, go to **Pages**.
4. Set **Source** to **Deploy from a branch**, then pick `main` and the **`/docs`** folder.
5. Save — your site will be live at `https://<username>.github.io/<repo-name>/` within a
   minute or two. Remember to rebuild and commit `docs/` again whenever you edit `content.py`,
   `templates/`, or `static/`.
